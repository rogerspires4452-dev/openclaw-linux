## Known bugs (found during VM validation, NOT yet fixed in the repo)

1. **Live mirrorlist is dead.** The image ships
   `/etc/pacman.d/mirrorlist` with every `Server =` line commented out
   (stock archiso template; the profile never generates/ranks mirrors).
   archinstall's dry-run then fails with "Failed to sync Arch Linux
   package database". Fix direction: stage an active mirrorlist in the
   profile (`Server = https://geo.mirror.pkgbuild.com/$repo/os/$arch`)
   or run reflector during the build. Workaround used in testing: copy a
   working mirrorlist over it in the live session before installing.
2. **Live pacman keyring is unpopulated.** pacstrap fails with "keyring
   is not writable / required key missing from keyring" until you run, in
   the live session: `rm -rf /etc/pacman.d/gnupg && pacman-key --init &&
   pacman-key --populate archlinux` (works because the cow overlay makes
   `/etc` writable). Fix direction: do that at build time (e.g. in
   `customize_airootfs.sh` or the profile's post-pacstrap step).
3. **Installed desktop user's home misses the Omarchy skel config.** The
   installed system boots to a **stock autogenerated Hyprland config**
   (SUPER+Q -> `kitty`, which is not even installed; the package set
   ships `foot`), not the `/etc/skel` Omarchy config (foot on SUPER+Return,
   waybar, etc.). Something between `useradd -m` and first login did not
   copy/populate `/etc/skel/.config` for the desktop user (issue #20
   work). Fix direction: verify skel copy timing in
   `install/install-openclaw.sh` / the first-boot unit, and confirm which
   user SDDM autologin actually starts.
4. **No file manager in the installed package set.** `PACKAGES_OPENCLAW`
   has `foot` + Hyprland + Chromium etc. but no nautilus/dolphin/thunar.
   Add one if a desktop file manager is wanted.
5. (Minor, test-rig only) qemu VM testing: archinstall mounts its target
   root under `/mnt` — don't 9p-mount anything at `/mnt` in the test VM;
   use `/sh`. Rapid qemu monitor `sendkey` bursts corrupt the guest input
   queue — pace keys ≥0.3 s.

## How to resume (build → burn → test)

1. Build: `sudo mkarchiso -v -w /tmp/archiso-tmp -o out .` from
   `archiso/` (or the systemd-run pattern in `archiso/README.md`).
   Apply fixes for bugs 1–3 first.
2. Burn: `sudo dd if=<iso> of=/dev/sdX bs=4M conv=fsync` — identify the
   target with `lsblk` first; the profile label is `OPENCLAW_202609`.
3. Smoke-test in qemu with OVMF before real hardware (see
   `archiso/README.md`); VM rig used for validation:
   `/home/roger/vm-usb-test/` on beelink (scratch.qcow2, share/ scripts,
   monitor sockets, screendumps).
4. Real-hardware guided install was still **outstanding** — the USB had
   just been re-burned with the #22 installer and no hardware test had run.
